# CAL 009 — Protección de la conversión cotización → orden

Fecha: 2026-11-09 (America/Los_Angeles). Solicitado por Fidel Calva ("Aplica el máster").

## Problema
`create-order-from-quote` usaba la llave de servicio y no verificaba identidad, rol ni propiedad.
Cualquiera con el id de una cotización podía crear una orden + factura, crear un cliente,
disparar solicitud de contrato por SMS y obtener el id de una orden existente.

## Qué cambió
- La función exige una de dos pruebas, verificadas en el servidor:
  1. El comprobante firmado que `save-quote` entrega al visitante que guardó **esa** cotización
     (HMAC, 72 h, ligado al quote_id), o
  2. Sesión de personal activo con rol permitido (admin, system_admin, owner, executive,
     ops_admin, sales, sales_admin, sales_rep, dispatcher, cs, cs_agent, customer_service),
     leído de `user_roles` vía `has_any_role`; si `staff_users.status` no es `active`, se rechaza.
- Sin prueba: 401 y no se crea ni se revela nada. Comprobante de otra cotización: 403.
- Id con formato inválido: 400. Cotización cancelada/perdida/vencida: 409.
  Visitante solo convierte estados draft, pending, saved, scheduled, checkout_started.
- Índice único `orders_quote_id_unique` (una orden por cotización). Dos solicitudes simultáneas
  devuelven la misma orden. Se verificó 0 duplicados antes de crearlo.
- Eventos `order_events` y `schedule_logs` registran si actuó el cliente o el personal (con actor_id).
- El firmado del comprobante se movió a `supabase/functions/_shared/quote-draft-token.ts`
  (save-quote y create-order-from-quote usan el mismo código).
- Cliente: `saveQuote()` devuelve `draftToken`; el flujo V3 lo envía al crear la orden.
  `PortalSchedule` usaba nombres de campo equivocados (`quote_id` / `order_id`); corregidos.

## Pruebas (backend real, sin SMS, email ni cobros)
- `bun test tests/create-order-auth.test.ts` — 8/8: sin id, id inválido, sin comprobante,
  comprobante alterado, comprobante de otra cotización, creación válida + reintento idempotente,
  orden existente no revelada sin comprobante, dos solicitudes simultáneas = una orden.
- `bun test tests/save-quote-auth.test.ts` — 11/11 (sin regresión tras mover el firmado).
- `bun test tests/save-quote-client-token.test.ts` — 1/1 (red simulada).
- Limpieza tras pruebas: se borraron 23 cotizaciones "Cal Test" (ZIP 99999) y 9 órdenes de prueba;
  el total de órdenes volvió a 69.

SQL de limpieza de pruebas (solo filas de prueba):
```sql
UPDATE public.quotes SET order_id = NULL WHERE zip_code='99999' AND customer_name='Cal Test';
DELETE FROM public.orders WHERE quote_id IN (SELECT id FROM public.quotes WHERE zip_code='99999' AND customer_name='Cal Test');
DELETE FROM public.quotes WHERE zip_code='99999' AND customer_name='Cal Test';
```

## No probado
- Envío final real en el navegador (dispara SMS y alertas reales). Verificado por partes:
  servidor (pruebas en vivo) y cliente (prueba con red simulada).
- Conversión hecha por personal con sesión real.

  cree la orden antes de enviar el enlace, o emitir un comprobante al generar el enlace.
